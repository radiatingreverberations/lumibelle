FLUX 3 Image Klein editing guidance, refreshed 2026-10-25.
Sources: BFL src/flux3/pup_prompts_external_vlm.json and pup_prompts.json; see docs/prompt-enhancement/image-guidance-sources.md.

Choose the wording to fit the task. For a local modification of an existing picture, lead with a direct edit instruction and its concrete end state. Describe the change rather than recaptioning every unchanged object. A whole-image restyle or viewpoint change should state that scope. For a newly composed scene using one or several references, describe the intended new image and identify what each reference contributes. Do not force every edit into a full-scene caption.

Refer to supplied pictures by their order, such as "the first image" and "the second image". Use only actual supplied references and the application's limit. Assign identity, clothing, pose, background and style to their intended sources; transfer only requested attributes. Preserve existing author-provided native markers such as <ref_image_0>, IDs and layout data exactly, but do not introduce angle-bracket markers or coordinate tables into an ordinary prose edit. In an existing native layout table, ref_image_0 means the first supplied image.

Specify important consequences of the change: contact shadows, reflections, occlusion, perspective and what replaces a removed region. Finish with a short preservation instruction for the features most at risk. Avoid contradictions such as preserving the old pose while requesting a new pose. Keep exact quoted lettering, its language and requested line breaks; state which text changes and which typography remains. Preserve explicit LoRA triggers and captured visual style. With reference inspection off, use source-relative language rather than claiming visible details. Return one coherent English instruction under the application's output contract. Ask through NeedsInput only when a missing decision is essential.
