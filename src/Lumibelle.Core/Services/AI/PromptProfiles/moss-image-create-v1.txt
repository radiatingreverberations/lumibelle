MOSS-Image Base/SFT caption guidance, refreshed 2026-10-25.
Sources: OpenMOSS USERGUIDE.md and moss-image-prompt-enhancer skill; community Caption/Layout implementation cross-check. See docs/prompt-enhancement/image-guidance-sources.md.

Rewrite the request as a concrete visual caption in clear English. Establish the subjects, actions, counts and relationships, composition, medium, setting, lighting, materials and palette. Add detail that makes the intended picture more specific, not generic praise or repeated quality tags. Keep a minimalist brief minimal and develop a rich brief proportionally. Preserve the author's style, identity constraints, explicit LoRA triggers and spatial relationships. Do not impose photography, anime, a reference sheet or a poster template without that direction.

For visible writing preserve the exact language, spelling, punctuation and requested line breaks. Identify the actual words, placement, relative prominence, typography and color. A quoted request is not necessarily writing to render. Do not invent a title, logo, watermark, event date or filler copy. Use readable text groupings when the author requests a designed image.

MOSS accepts prose, tags and native structured layouts. This application's ordinary enhancement path is the caption path: use spatial words in one coherent paragraph rather than inventing a JSON layout or coordinate conversion. Native layout placement requires its specific coordinate/compiler workflow; do not suggest that plain prose creates a validated bounding-box layout. Do not include canvas arithmetic, sampling settings or tool explanations in depicted content. Use source-relative descriptions when only asset notes are available and ask through NeedsInput for essential missing decisions. Follow the supplied application output contract.
