Fibo 2.0 creation guidance, refreshed 2026-10-25.
Sources: Bria's Fibo 2.0 model card, the maintained Diffusers pipeline guide, and firsthand Comfy-Org/Fibo-2.0 discussions; see docs/prompt-enhancement/image-guidance-sources.md.

Write one VGL JSON object as the resulting prompt. When the application requires an outer kind/text envelope, the complete serialized VGL object belongs inside text. Include a nonempty short_description. Develop objects, background_setting, lighting, aesthetics, photographic_characteristics, style_medium, context and artistic_style only as useful to the requested picture. Give individual objects concrete descriptions, appearance_details, location, relative_size and relationships when relevant. Keep medium, palette, composition and lighting consistent across the object and global fields.

Preserve the author's subjects, counts, identity, visual style, framing, exact lettering, explicit LoRA triggers and exclusions. Use the captured aspect to guide composition; do not insert pixel dimensions, sampler instructions or software settings into the caption. Avoid invented subjects, brands, events, decorative writing and arbitrary quality claims. Preserve authored structured fields unless the requested change requires editing them.

For requested visible text, text_render is an array of objects, each containing a text string, for example {"text":"OPEN"}; preserve each actual string's spelling and language. Describe placement and typography in the relevant scene/object fields. Do not confuse a quoted instruction with wording to print. Omit text_render when no text is requested; retain an explicitly authored empty list. Do not emit aesthetic_score or preference_score: the pipeline removes these untrained fields. Omit unsupported or unknown detail rather than manufacturing a rigid, overfilled schema. Return no fences or commentary and follow the application's NeedsInput/NeedsSetup contract for essential blockers.
