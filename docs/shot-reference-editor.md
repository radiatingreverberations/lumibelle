# Manual shot references

Click **Environment** to link an environment library. Select the asset and click **Use environment** to save only that association; existing references and prompt text stay intact. Browse views or choose them with AI separately, then use **Apply views** to attach the reviewed pictures.

In Shots, click **Edit references** in the References action row to open Manage references. Browse asset images and reels, arrange each selected list, and expand an image to edit its purpose, character link, crop, and preservation guidance. Reels offer **Keyframes / Full reel / None**. [Character voices](h3/character-voices.md) are chosen once per character, independently of appearance; environment and legacy soundtrack controls remain available. Picture numbers follow ordinary images, then each reel's selected keyframes in order. Changes stay in the dialog until **Apply changes** saves visuals and voices together with one Undo step; Cancel discards them. A failed save or conflicting edit keeps the dialog draft available.

Each selected reel shows its resolution in MP. Its ⇄ **Replace reel** button lists the other reels of the same asset, a reel regenerated from it first, then the same look and the sharpest, so a Quick reel can be swapped for its Native regeneration. While it is open, the reference list shows reels only and each card offers **Replace Video N** instead of Add reel, also when the shot already has three reels. The swap keeps the reference's name, use guidance, visuals, soundtrack and voice; keyframes move to the same moments and RefMod frames are captured again. When other shots use the old reel, **Also replace it in N other shots** applies the same swap there on Apply. If the swap is the only change, a reviewed prompt stays reviewed, as with **Replace in shots…** in Assets ([reference reels](h3/reference-reels.md)). A reel of another asset, and **Replace reel** in the reference settings, start from the chosen reel's library defaults instead.

On narrow screens, switch between **Browse** and **Selected**. Filters and edits survive these switches. The nine-picture limit includes frame anchors and reel keyframes. [Reel keyframes](h3/reel-keyframes.md) stay inside their reel; setup overrides do not change library defaults. Ordinary take frames can still be saved to Assets through the take player.

The References panel summarizes the submitted order and purposes. Reordering, editing, and removal live in the dialog; row actions appear only when a reference needs repair or restoration.

In **Manage references** (in Shots and in the Assets image composer) and a reel's **Manage reel references**, a picture whose image has been moved to Trash shows **In Trash · N days remaining** with **Restore image**, which returns the image to its asset without discarding other pending edits. Restoring an image from a deleted asset recreates that asset. Restore is offered only when it returns the image to the asset the reference names. Expired images, images being permanently deleted, images moved to another asset before being trashed, and removed standalone frames still need replacing or removing.

**First frame** and **Last frame** are exclusive purposes, with at most one image for each endpoint. Selecting either clears that image's character link and identity/look purpose, without removing the character from the shot. An anchor can belong to any Asset category. Character starting/ending looks describe clothing or styling and remain separate from whole-frame anchors.

Anchors use image-level preservation guidance or an explicit shot override. Shared asset and look instructions are excluded. The compiler follows the bundled [Ref2VA guide](h3/ref2va-prompt-guide.md): standalone Picture definitions, keyframe-completion task type, endpoint retention, and opening/ending instructions around the action. The submitted crop is the target composition. This expresses prompt guidance and does not guarantee exact endpoints or switch to FL2VA.

Fill controls, scene-setup editors, and preferred-reference editors have been retired. Existing shot selections, shared guidance, and inert setup metadata remain saved; no content migration or generation is performed. Refresh Assets reloads available images and guidance without changing the chosen references.

Existing shots without anchors compile identically. Queued requests retain their captured image order, roles, crops, guidance, and prompt through recovery and added candidates. Verification uses synthetic fixtures and mocked providers; GPU adherence has not been evaluated in this pass.
